# HUD implementation coverage

This describes the 0.2.0-alpha.11 implementation, inspected against installed Forever addon source and exercised with Lua 5.1 mock widgets. It has **not** been validated inside World of Warcraft. vasagoio never launches the game, installs/enables dependency addons, changes actions or bindings, or enables combat-data access.

## Persistence and restoration

Bartender, Prat and SexyMap changes use exact SavedVariables paths. Details keeps live window configuration in `Details.tabela_instancias[1]` and serializes it into the active profile; its snapshot deliberately resolves that live table again after reload. **Details must be loaded for restoration.** Setup neither loads nor enables it. Only scalar/appearance/geometry fields are snapshotted; combat, actor, chat and inventory data are not included.

Prepare functions return plans without applying settings. Core validates target identity, previews changes, snapshots them and checks for intervening edits before writing. Reload after setup or rollback so owners rebuild their frames from the restored configuration. The Details adapter deliberately avoids a broad live `ChangeSkin(nil)` call, which can normalize extra fields and undermine an exact snapshot. Disabling vasagoio removes ongoing presentation after reload; restoring dependency profiles is a separate operation.

## Verification

`tests/hud_spec.lua` verifies plan-only review, every persistent path resolving to its exact target, native action/paging preservation, button scale/offset math, pet alignment, wide-screen canvas origins, owner absence/schema refusal, chat/map/meter dimensions, cooldown state transitions and native handler preservation, restricted-value guards, and no signals on ordinary buffs. Actual FUF pool integration tests cover late allocation, plain/free/live button records, harmful/dispel distinction, native duration placement, refused widgets and zero aura-data queries. It also verifies no HUD geometry or aura-pool refresh in combat. `tests/hud_lifecycle_spec.lua` additionally covers the single bottom map overlay, scale-correct bounded labels, native chat handlers and notification preservation, scoped owner callbacks, disable/reactivation baselines, combat deferral and unsupported-version refusal. These suites and Lua 5.1 syntax validation passed. These mocks cannot validate protected-frame/taint behavior, pixel rendering, live owner callbacks or native combat restrictions; those remain user-run checks.

## Performance correction and acceptance

The alpha.3 user test reported 90–120 FPS before vasagoio and approximately30 with it enabled; disabling vasagoio isolated the main regression. Alpha.4 scopes action/unit refreshes, coalesces event bursts, bounds reentrant callbacks, caches unchanged surfaces and filters aura refreshes by affected units/buttons. Closed windows wait for visibility; stationary native interiors are no longer repainted on every discovery tick. New generic controls without a reviewed owner callback may need a window reopen or `/vasagoio refresh`.

`/vasagoio perf` reports module-application counts, failures and elapsed timings since UI load, where the client provides a clock. Direct widget/ticker callbacks and other addons are outside those timings. It does not enable CPU profiling or measure FPS. Offline operation counts demonstrate removed redundant work. The user reported that performance was better after the earlier correction. A controlled frame-rate comparison remains pending until the user compares the same scene, camera and graphics with vasagoio on/off, reloading between runs and leaving Skinner unchanged.

## Alpha.11 compatibility review

The new Details Forever/Camelot package was compared with the exact 15410 baseline: 335 source files, 309 unchanged, 26 changed, none removed. Core window sizing, instance schema, row text, skin and LibWindow contracts are unchanged. Its three window_main.lua changes concern native class-icon parenting/click handling, which this adapter does not modify. The new profile_keep_window_sizes preference is preserved. Both exact builds pass preparation/runtime fixtures; malformed schemas and unknown future builds remain refused. This changes compatibility admission only, retaining design revision 12/preset5 and the full 248×186 headerless meter. [Publisher file list](https://www.curseforge.com/wow/addons/details/files/all).
