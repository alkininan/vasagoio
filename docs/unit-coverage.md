# Unit and nameplate implementation coverage

This is source-audited implementation, not an in-game verification claim. The supported schemas are **Forever Unit Frames 0.79.1, 0.81.0 and 0.81.1** and **Threat Plates 13.3.9**. Other versions refuse profile setup until reviewed. WoW has not been launched or controlled to test this release.

All dimensions below are the 2560×1440 design reference. Setup converts them through the shared uniform scale; FUF snaps its dimensions to whole UI units. Setup checks resulting sizes against the owner's actual schema bounds and identifies the failing field if scaling would clamp it. Each field is checked before writing. The16px resting/status badge has a native minimum10 UI units, and the28px attached-party-pet aura has a native maximum40 UI units. Larger scales are refused with a named field rather than silently clamped. Layouts must be checked at the user's actual resolution and UI scale.

## Profile and rollback behavior

Preparing either setup plan is read-only. Every change has a SavedVariables path for the setup engine's persistent rollback record. Both owners receive newly named profiles on every setup apply, with a per-character pointer selecting the new profile after reload. FUF's private live profile and TP's live AceDB tables remain intact until reload. Previous profiles remain present. Raid changes preserve existing nonappearance settings. TP copies existing filters and unique-nameplate rules; dual-spec slots that shared the previous profile now share its themed copy, while independently chosen spec profiles stay intact. Its audited AceDB logout handler does not reset the selected-profile pointer. Reload after applying or restoring profiles.

Disabling the unit module stops its hooks, hides its surfaces/edges, restores tracked owner text/bar colors and reclaims XP/party-pet child geometry. Geometry restoration waits for combat to end and preserves newer owner writes. A changed owner profile/version also releases the active decorations on the next owner update or unit event. Unchecking the addon and reloading removes hooks and surfaces. Profiles are separate: use the setup engine's profile restore when also reverting owner configuration.

No upstream code or media is included.

`tests/unit_adapters_spec.lua` checks read-only preparation, rollback paths, exact reference row math, preserved user settings, fresh owner profile names, ordinary/regional TP identities and spec bindings, version/scale refusal, native opaque-value pass-through, owner offline text, party-pet dimensions/gaps/absent units/combat deferral and disabled hooks. Run it from the repository root with `lua tests/unit_adapters_spec.lua`. The installed FUF0.81.0 schema accepted all730 current proposed settings without clamping or unsupported keys at effective scales0.625,1.00 and1.40. Scales0.50 and1.50 are now explicitly refused for the status-badge minimum and attached-pet-aura maximum. Offline tests also cover profile/disable cleanup and event behavior. `tests/player_progress_spec.lua` checks fixed outer geometry, XP-only reclaim, full/height-only owner relayouts and combat deferral. `tests/unit_states_spec.lua` checks combat/aggro, opaque threat pass-through, own-pet mood fallbacks, text restoration and unchanged cast semantics.

## Idle rows and scoped updates

New raid resource-color fields use the shared palette, and the missing-health track retains the neutral background. A read-only check against the installed owner's schema accepted all 690 proposed values without normalization. Earlier 0.79.1 remains supported without writing these newer fields.

Actual enabled cast bars remain available during casts; TinyThreat remains the selected threat meter. Unit creation and roster callbacks request only the unit-frame module, so they do not trigger unrelated window styling. Applying this profile correction requires setup and reload.

Reproduce the source-only audit with `lua tests/fuf_schema_audit.lua <FUF-source-directory>` from the repository root. The newer party wrapping and raid color fields remain applied. This is source/registry evidence, not a binary comparison with 0.81.0 or native combat/rendering proof.
