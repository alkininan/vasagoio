# HUD implementation coverage

This is an alpha implementation, inspected against installed Forever addon source and exercised with Lua 5.1 mock widgets. It has **not** been validated inside World of Warcraft. vasagoio never launches the game, installs/enables dependency addons, changes actions or bindings, or enables combat-data access.

All dimensions above are reference values on 2560×1440. The core converts them uniformly to current UIParent units and centers the reference canvas on other aspect ratios; it does not change UIParent scale. Geometry, material colors and typography come from shared tokens. Profiles are recalculated only during an explicit setup review, not overwritten on every login or screen-size change.

## Persistence and restoration

Bartender, Prat and SexyMap changes use exact SavedVariables paths. Details keeps live window configuration in `Details.tabela_instancias[1]` and serializes it into the active profile; its snapshot deliberately resolves that live table again after reload. **Details must be loaded for restoration.** Setup neither loads nor enables it. Only scalar/appearance/geometry fields are snapshotted; combat, actor, chat and inventory data are not included.

Prepare functions return plans without applying settings. Core validates target identity, previews changes, snapshots them and checks for intervening edits before writing. Reload after setup or rollback so owners rebuild their frames from the restored configuration. The Details adapter deliberately avoids a broad live `ChangeSkin(nil)` call, which can normalize extra fields and undermine an exact snapshot. Disabling vasagoio removes ongoing presentation after reload; restoring dependency profiles is a separate operation.

## Source contracts examined

These paths refer to each dependency's own public source package; no source was copied into vasagoio.

- Bartender4: `Bartender4.lua`, `ActionBars.lua`, `ActionBar.lua`, `Bar.lua`, `ButtonBar.lua`, `PetBar.lua`, `PetButton.lua`; bundled LibWindow position storage and LibActionButton widget/range/cooldown contracts. `CONFIG_VERSION=3` is required.
- Prat-3.0 3.9.117: `addon/addon.lua`, `addon/modules.lua`, `modules/Font.lua`, bundled AceAddon/AceDB; Font is the short module lookup name, while `Prat_Font` is the saved namespace. Alpha.6 verifies that namespace and active profile identities before proposing `size[ChatFrameN]`/font changes. Disabled Font is reported separately. The profile-engine regression covers read-only review, stale profile/module state, apply and restore.
- SexyMap: `SexyMap.lua`, `Borders.lua`, `Shapes_Classic.lua`, `ZoneText.lua`, `Clock.lua`; character/global profile selection and owner scale, mask, position and zone-color behavior.
- Details: `API UI.txt`, `classes/include_instance.lua`, `classes/class_instance.lua`, `core/windows.lua`, `functions/profiles.lua`, `functions/rowtexts.lua`; live instance schema, documented `GetInstance` / `ChangeSkin(nil)`, background and LibWindow fields.
- ForeverUnitFrames 0.79.1 and 0.81.0: `Elements/Auras.lua`, `Elements/AuraContainers.lua`, `Elements/AuraButton.lua`, `Core/Settings.lua`; owner pool references, actual group filters, secure-container restrictions and native countdown widget. No private owner function is replaced or called.

## Verification

`tests/hud_spec.lua` verifies plan-only review, every persistent path resolving to its exact target, native action/paging preservation, button scale/offset math, pet alignment, wide-screen canvas origins, owner absence/schema refusal, chat/map/meter dimensions, cooldown state transitions and native handler preservation, restricted-value guards, and no signals on ordinary buffs. Actual FUF pool integration tests cover late allocation, plain/free/live button records, harmful/dispel distinction, native duration placement, refused widgets and zero aura-data queries. It also verifies no HUD geometry or aura-pool refresh in combat. Lua syntax validation and this suite passed. These mocks cannot validate protected-frame/taint behavior, pixel rendering, live owner callbacks or native combat restrictions; those remain user-run checks.

## Performance correction and acceptance

The alpha.3 user test reported 90–120 FPS before vasagoio and approximately30 with it enabled; disabling vasagoio isolated the main regression. Alpha.4 scopes action/unit refreshes, coalesces event bursts, bounds reentrant callbacks, caches unchanged surfaces and filters aura refreshes by affected units/buttons. Closed windows wait for visibility; stationary native interiors are no longer repainted on every discovery tick. New generic controls without a reviewed owner callback may need a window reopen or `/vasagoio refresh`.

`/vasagoio perf` reports module-application counts, failures and elapsed timings since UI load, where the client provides a clock. Direct widget/ticker callbacks and other addons are outside those timings. It does not enable CPU profiling or measure FPS. Offline operation counts demonstrate removed redundant work; actual frame-rate recovery remains unverified until the user compares the same scene, camera and graphics with vasagoio on/off, reloading between runs and leaving Skinner unchanged.
